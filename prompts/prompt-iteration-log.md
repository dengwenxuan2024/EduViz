# 提示词迭代优化日志


## 1.0 初版

核心功能：
- 支持三表（classes、students、grades）关联查询
- 支持柱状图、折线图、饼图三种图表类型
- 最多生成3张图表
- 基础异常处理（SQL错误提示）

提示词结构：
- 角色定义
- 核心能力
- 数据库表结构
- 表间关联关系
- 工作流程
- 输出格式要求
- 约束条件
- 补充规则

已知限制：
- 仅支持3种图表类型
- 图表生成数量限制为3张
- 未明确数据库连接规则


## 1.1 生图工具选择——ECharts

修改1：第四步标题 + 规则强化

将第四步标题改为"图表生成（关键步骤）"，增加"支持多图表生成"规则说明。

重要规则：支持多图表生成
如果用户需求包含多个维度或指标，你需要为每个维度分别调用一次 ECharts 图表生成工具，并最终将所有图表一起呈现。

修改2：新增"判断需要生成几张图"规则

判断需要生成几张图：
- 用户明确指定单一指标（如"平均分"）→ 1张图
- 用户宽泛提问（如"分析成绩""整体情况"）→ 2~3张图

修改3：新增"多图表生成执行流程"完整章节

新增多图表生成的标准化执行流程，包括：数据获取 → 图表清单确定 → 逐张调用工具 → 整合回复。

修改4：新增约束条件

- 每张图的数据必须是独立的、完整的分析维度
- 总图表数量不超过3张（避免回复过长）

修改5：表结构明晰

完善表间关联关系，明确三表JOIN路径。


## 1.2 生图工具选择——AntV 可视化图表

修改10：从第五步到约束条件整体调整

将图表工具从 ECharts 切换为 AntV 可视化图表，调整数据格式要求（ECharts 用 ; 分隔 → AntV 用 JSON 数组字符串）。

图表类型选择更新：
- 类别对比 → 柱状图（工具名：生成柱状图）
- 时间趋势 → 折线图（工具名：生成折线图）
- 占比分布 → 饼图（工具名：生成饼图）

修改11：添加数据库连接强制规则

新增最高优先级的数据库连接规则，禁止传递 db_uri 参数。

数据库连接强制规则（最高优先级，必须严格遵守）：
- 调用 sql_execute 工具时，只传递 query 参数，绝对禁止传递 db_uri 参数
- 正确调用格式：{"sql_execute": {"query": "SELECT ..."}}

修改12：增加最终回复格式要求

新增图表图片嵌入规则，要求使用 Markdown 图片语法嵌入 imageUrl。

图表图片嵌入规则：
- 调用 AntV 图表工具后，工具会返回一个包含 imageUrl 的响应
- 必须在最终回复中，使用 Markdown 图片语法嵌入该图片链接
- 格式：![图表描述](imageUrl)

修改13：完善最终回复格式要求（从工具响应中提取图片链接）

明确工具返回 JSON 对象格式，规范图片链接提取步骤。

修改14：再次修改最终回复格式部分

工具返回混合格式（纯文本 URL + JSON），完善提取规则。

调用 AntV 图表工具后，工具会返回混合格式的响应，包含纯文本 URL 和 JSON 两种形式：
https://.../original{"imageUrl": "https://.../original"}

原因：部分模型（如 kimi-k2-thinking）对 JSON 结构解析不稳定，需要明确提取规则。

## 6.0 增加异常处理

修改30：增加异常处理章节、修改约束条件条目

新增完整的异常处理章节，定义5种异常场景及处理方式：

| 异常类型 | 触发条件 | 处理方式 |
|----------|---------|----------|
| SQL语法错误 | Database工具返回SQL语法错误 | 分析错误，修正SQL并重新执行，最多重试2次 |
| 数据不存在 | SQL执行成功但返回空结果 | 向用户说明，主动跳过该需求，继续执行其他任务 |
| 超出迭代次数 | Agent连续执行超过最大迭代次数（50次） | 系统强制终止并返回错误提示 |
| 图表生成失败 | AntV工具返回错误或图片URL无效 | 跳过该图表，继续生成剩余图表 |
| 工具调用异常 | Database或AntV工具调用时出现非预期错误 | 尝试重新调用一次，若仍失败则跳过 |


## 问题汇总

### 问题1：ECharts 图表在 Agent 模式下无法显示

状态：已解决（换用 AntV）

问题根源：Agent 模式下，工具返回的 ECharts JSON 配置需要特殊的渲染处理，而 Dify 的聊天界面在 Agent 模式下不支持自动渲染 ECharts 工具返回的 JSON 配置。Agent 将 ECharts 返回的 JSON 配置当作普通文本信息处理，最终整合成文字报告，图表配置被当作"背景信息"。

解决方案：换用 AntV 可视化图表工具（返回图片 URL，可直接在 Agent 模式下显示）。


### 问题2：Agent 始终连接 SQLite 而非 MySQL

状态：已解决（修改8、9、11）

问题根源：Agent 调用 SQL 工具时主动传递了错误的 db_uri 参数，覆盖了 Database 工具配置的默认数据源。

解决方案：在 System Prompt 中增加数据库连接强制规则，明确禁止传递 db_uri 参数。


### 问题3：AntV 正常调用但 Agent 不返回图片

状态：已解决（修改12）

问题根源：Agent 生成网页链接但不返回内容，未在最终回复中嵌入图片链接。

解决方案：增加最终回复格式要求，明确要求使用 Markdown 图片语法嵌入 imageUrl。


### 问题4：部分模型不显示图片（kimi-k2.5、kimi-k2-thinking）

状态：改善但未完全解决（修改14）

问题根源：工具返回混合格式响应（纯文本 URL + JSON），部分模型对 JSON 结构解析不稳定，提取 imageUrl 字段时出现偏差。

解决方案：完善从工具响应中提取图片链接的规则说明，明确混合格式的处理方式。


### 问题5：DeepSeek-V3.2 SQL 生成阶段的"幻觉"现象

状态：未解决

问题根源：DeepSeek-V3.2 性能较低，在生成 SQL 过程中偶然出现乱码/错误。

影响：表现为 SQL 中混入非 SQL 字符（如 body{color: #333;}.2），导致语法错误。

建议：当前版本不推荐使用 DeepSeek-V3.2，建议使用 qwen3-max 或 qwen3.7-plus。


### 问题6：一次性生成7张图超出迭代次数限制

状态：已解决（修改17）

问题根源：Agent 最大迭代次数为10次，生成7张图需要大量工具调用，总调用次数超过10次。

解决方案：将 Agent 最大迭代次数从10次增加到20次。


### 问题7：箱线图生成非常慢

状态：部分优化（修改18尝试解决但存在副作用）

问题根源：箱线图查询拉取整张表的数据，数据传输量大。

尝试方案：使用窗口函数预计算五数概括（修改18），但导致箱体消失。

当前状态：箱线图优化仍在进行中，建议后续使用采样或限制数据量方式优化。


### 问题8：修改18后箱线图箱体消失

状态：已解决（删除修改18）

问题根源：箱线图工具要求每个分类（班级）必须有多个数值才能绘制箱体。传入的是每个班级的五个统计量（min/q1/median/q3/max）各一个值，工具无法构造箱体，只能显示为点或须线。

解决方案：删除修改18，改用原始数据生成箱线图。


### 问题9：瀑布图数据从0开始

状态：已解决（修改19）

问题根源：各科目独立对比时应从0开始，而非累积浮动。

解决方案：明确瀑布图适用场景规则：
- 累积变化（如各学期总成绩）→ 瀑布图
- 独立对比（如各科成绩）→ 柱状图/条形图
